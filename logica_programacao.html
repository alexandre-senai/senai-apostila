Protocolo

O que é HTTP e HTTPS

HTTP (HyperText Transfer Protocol) é o protocolo de comunicação usado na web. Ele define como mensagens são formatadas e transmitidas entre um cliente (navegador, app) e um servidor.

HTTPS = HTTP + TLS/SSL (criptografia). Todo o tráfego é cifrado, o que impede interceptação de dados ("homem no meio"). Em produção, sempre use HTTPS.

Requisição / Resposta

Header (Cabeçalho)

Os headers são metadados trafegados junto à requisição ou resposta. Eles informam o tipo do conteúdo, autenticação, cache, origem, idioma e muito mais.

Headers de requisição comuns

HeaderO que faz
Content-TypeInforma o formato do body enviado (ex.: application/json)
AuthorizationEnvia credenciais — geralmente Bearer <token>
AcceptInforma quais formatos o cliente aceita como resposta
CookieEnvia cookies armazenados no navegador

Headers de resposta comuns

HeaderO que faz
Content-TypeFormato do body da resposta
Set-CookieOrdena ao navegador salvar um cookie
Cache-ControlPolítica de cache (ex.: no-cache, max-age=3600)
Access-Control-Allow-OriginPolítica de CORS
// Exemplo: fetch com headers customizados
const response = await fetch('/api/users', {
  method: 'GET',
  headers: {
    'Content-Type': 'application/json',
    'Authorization': `Bearer ${token}`,
  },
});
Requisição / Resposta

Body (Corpo)

O body é o conteúdo da mensagem — presente em requisições POST, PUT, PATCH e na maioria das respostas. O formato mais comum em APIs modernas é JSON.

O header Content-Type: application/json deve ser enviado sempre que o body for JSON.

Body de requisição (POST)

// Enviando um body JSON
await fetch('/api/login', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ email: 'alex@senai.br', senha: '1234' }),
});

Body de resposta (servidor)

// Node.js / Express — resposta JSON
app.get('/api/users/:id', (req, res) => {
  res.status(200).json({
    id: 1,
    nome: 'Alexandre',
    cargo: 'Instrutor SENAI',
  });
});

Autenticação

O que é JWT

JWT (JSON Web Token) é um padrão aberto (RFC 7519) para transmitir informações de forma segura entre partes como um objeto JSON assinado digitalmente.

Um JWT é uma string dividida em 3 partes separadas por ponto (.):

xxxxx.yyyyy.zzzzz
   ↑       ↑       ↑
Header  Payload Signature
Header
Tipo do token e algoritmo de assinatura (ex.: HS256)
Payload
Dados do usuário (id, role, expiração…) — NÃO cifrados!
Signature
Garante que o token não foi adulterado
Atenção: O payload é apenas codificado em Base64 — não cifrado. Nunca coloque senhas ou dados sensíveis no payload.

Como o JWT funciona

O fluxo de autenticação com JWT segue este ciclo:

Cliente
faz login
→
Servidor
valida credenciais
→
Gera JWT
assina com secret
→
Retorna
token ao cliente
→
Req. protegida
envia Bearer token
→
Servidor valida
e responde
  • 1 Usuário envia e-mail e senha via POST.
  • 2 Servidor verifica as credenciais no banco.
  • 3 Se válido, gera um JWT assinado com uma chave secreta.
  • 4 Cliente armazena o token (memória, cookie httpOnly).
  • 5 Nas próximas requisições, envia o token no header Authorization: Bearer <token>.
  • 6 Servidor verifica a assinatura e valida a expiração antes de responder.

Implementando JWT — React + Node (TypeScript)

1. Instalação das dependências

# Back-end
npm install jsonwebtoken bcryptjs
npm install -D @types/jsonwebtoken @types/bcryptjs

# Front-end
npm install axios

2. Back-end — gerar e validar o token

src/auth/authController.ts
import { Request, Response } from 'express';
import jwt from 'jsonwebtoken';
import bcrypt from 'bcryptjs';

const JWT_SECRET = process.env.JWT_SECRET ?? 'troque-em-producao';

// Payload tipado
interface TokenPayload {
  userId: number;
  email: string;
}

export async function login(req: Request, res: Response) {
  const { email, senha } = req.body;

  // Busca usuário no banco (exemplo simplificado)
  const usuario = await buscarUsuarioPorEmail(email);
  if (!usuario) return res.status(401).json({ erro: 'Credenciais inválidas' });

  const senhaCorreta = await bcrypt.compare(senha, usuario.senhaHash);
  if (!senhaCorreta) return res.status(401).json({ erro: 'Credenciais inválidas' });

  const payload: TokenPayload = { userId: usuario.id, email: usuario.email };

  const token = jwt.sign(payload, JWT_SECRET, { expiresIn: '8h' });

  res.json({ token });
}
src/auth/authMiddleware.ts
import { Request, Response, NextFunction } from 'express';
import jwt from 'jsonwebtoken';

const JWT_SECRET = process.env.JWT_SECRET ?? 'troque-em-producao';

export function autenticar(req: Request, res: Response, next: NextFunction) {
  const authHeader = req.headers.authorization;

  if (!authHeader?.startsWith('Bearer ')) {
    return res.status(401).json({ erro: 'Token ausente' });
  }

  const token = authHeader.split(' ')[1];

  try {
    const decoded = jwt.verify(token, JWT_SECRET);
    (req as any).usuario = decoded;
    next();
  } catch {
    res.status(401).json({ erro: 'Token inválido ou expirado' });
  }
}

3. Front-end React — login e requisições autenticadas

src/hooks/useAuth.ts
import { useState } from 'react';
import axios from 'axios';

export function useAuth() {
  const [token, setToken] = useState<string | null>(null);

  async function login(email: string, senha: string) {
    const { data } = await axios.post('/api/auth/login', { email, senha });
    setToken(data.token);
    // Opção: salvar em cookie httpOnly pelo servidor
  }

  function logout() { setToken(null); }

  const api = axios.create({
    baseURL: '/api',
    headers: token ? { Authorization: `Bearer ${token}` } : {},
  });

  return { token, login, logout, api };
}
Boas práticas: Prefira cookies httpOnly; Secure; SameSite=Strict ao localStorage para guardar JWTs em produção — protege contra ataques XSS.

O que é Middleware

Middleware é uma função que fica no meio do ciclo de vida de uma requisição HTTP — entre o cliente e o handler final. Ela recebe o objeto request e response e decide se processa a requisição, modifica algo, ou passa adiante com next().

Requisição
→
Middleware 1
Logger
→
Middleware 2
Autenticação
→
Middleware 3
Validação
→
Handler
Resposta

Usos comuns de middlewares

TipoO que faz
LoggerRegistra método, URL e tempo de resposta de cada requisição
AutenticaçãoVerifica se o token JWT é válido antes de continuar
AutorizaçãoCheca se o usuário tem permissão para acessar o recurso
ValidaçãoValida o body da requisição (ex.: zod, joi)
CORSAdiciona headers de Cross-Origin Resource Sharing
Rate LimitingLimita número de requisições por IP/período
Error HandlerCaptura erros não tratados e retorna resposta padronizada

Criando middlewares em Express + TypeScript

src/middlewares/logger.ts
import { Request, Response, NextFunction } from 'express';

export function logger(req: Request, res: Response, next: NextFunction) {
  const inicio = Date.now();
  res.on('finish', () => {
    console.log(`[${req.method}] ${req.url} → ${res.statusCode} (${Date.now() - inicio}ms)`);
  });
  next(); // passa para o próximo middleware
}
src/middlewares/errorHandler.ts
import { Request, Response, NextFunction } from 'express';

export function errorHandler(
  err: Error, req: Request, res: Response, next: NextFunction
) {
  console.error(err.stack);
  res.status(500).json({ erro: 'Erro interno do servidor' });
}
src/app.ts
import express from 'express';
import { logger }       from './middlewares/logger';
import { autenticar }   from './auth/authMiddleware';
import { errorHandler } from './middlewares/errorHandler';

const app = express();

// Middlewares globais
app.use(express.json());
app.use(logger);

// Rota pública
app.post('/api/auth/login', login);

// Rotas protegidas — autenticar é o middleware
app.get('/api/users', autenticar, listarUsuarios);

// Sempre por último — captura erros
app.use(errorHandler);
A ordem importa: middlewares de erro precisam de 4 parâmetros (err, req, res, next) e devem ser registrados após todas as rotas.
Banco de dados

Conectar PostgreSQL com Node.js (TypeScript)

A biblioteca mais usada para conectar Node.js ao PostgreSQL é o node-postgres (pg). Para TypeScript, é comum também usar um ORM como Prisma ou TypeORM. Veja as duas abordagens:

Opção A — pg (driver nativo, sem ORM)

# Instalação
npm install pg
npm install -D @types/pg
src/database/pool.ts
import { Pool } from 'pg';

export const pool = new Pool({
  host:     process.env.DB_HOST     ?? 'localhost',
  port:     Number(process.env.DB_PORT)  || 5432,
  database: process.env.DB_NAME     ?? 'minha_db',
  user:     process.env.DB_USER     ?? 'postgres',
  password: process.env.DB_PASSWORD ?? 'senha',
  max: 10, // máximo de conexões no pool
});
src/users/userRepository.ts
import { pool } from '../database/pool';

interface Usuario {
  id: number;
  nome: string;
  email: string;
}

export async function listarUsuarios(): Promise<Usuario[]> {
  const { rows } = await pool.query('SELECT id, nome, email FROM usuarios');
  return rows;
}

export async function buscarPorId(id: number): Promise<Usuario | null> {
  const { rows } = await pool.query(
    'SELECT id, nome, email FROM usuarios WHERE id = $1',
    [id] // parameterizado — previne SQL injection
  );
  return rows[0] ?? null;
}

export async function criarUsuario(nome: string, email: string, senhaHash: string) {
  const { rows } = await pool.query(
    'INSERT INTO usuarios (nome, email, senha_hash) VALUES ($1, $2, $3) RETURNING *',
    [nome, email, senhaHash]
  );
  return rows[0];
}

Opção B — Prisma ORM (recomendado para novos projetos)

  provider = "postgresql"
  url      = env("DATABASE_URL")

generator client {
  provider = "prisma-client-js"
}

model Usuario {
  id        Int      @id @default(autoincrement())
  nome      String
  email     String   @unique
  senhaHash String   @map("senha_hash")
  criadoEm  DateTime @default(now()) @map("criado_em")
}
# Gerar o cliente e aplicar migrations
npx prisma migrate dev --name init
npx prisma generate
src/database/prisma.ts
import { PrismaClient } from '@prisma/client';

// Instância única (singleton)
const prisma = new PrismaClient();
export default prisma;
src/users/userService.ts
import prisma from '../database/prisma';

export async function listarUsuarios() {
  return prisma.usuario.findMany({
    select: { id: true, nome: true, email: true },
  });
}

export async function criarUsuario(nome: string, email: string, senhaHash: string) {
  return prisma.usuario.create({
    data: { nome, email, senhaHash },
  });
}
