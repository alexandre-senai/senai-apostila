Protocolo

O que é HTTP e HTTPS

HTTP (HyperText Transfer Protocol) é o protocolo de comunicação usado na web. Ele define como mensagens são formatadas e transmitidas entre um cliente (navegador, app) e um servidor.

HTTPS = HTTP + TLS/SSL (criptografia). Todo o tráfego é cifrado, o que impede interceptação de dados ("homem no meio"). Em produção, sempre use HTTPS.

Protocolo
Baseado em texto, stateless
Portas padrão
HTTP → 80  |  HTTPS → 443
Modelo
Requisição → Resposta
Segurança HTTPS
Certificado TLS (ex.: Let's Encrypt)

Requisição / Resposta

Header (Cabeçalho)

Os headers são metadados trafegados junto à requisição ou resposta. Eles informam o tipo do conteúdo, autenticação, cache, origem, idioma e muito mais.

Headers de requisição comuns

HeaderO que faz
Content-TypeInforma o formato do body enviado (ex.: application/json)
AuthorizationEnvia credenciais — geralmente Bearer <token>
AcceptInforma quais formatos o cliente aceita como resposta
CookieEnvia cookies armazenados no navegador

Headers de resposta comuns

HeaderO que faz
Content-TypeFormato do body da resposta
Set-CookieOrdena ao navegador salvar um cookie
Cache-ControlPolítica de cache (ex.: no-cache, max-age=3600)
Access-Control-Allow-OriginPolítica de CORS
// Exemplo: fetch com headers customizados
const response = await fetch('/api/users', {
  method: 'GET',
  headers: {
    'Content-Type': 'application/json',
    'Authorization': `Bearer ${token}`,
  },
});
Requisição / Resposta

Body (Corpo)

O body é o conteúdo da mensagem — presente em requisições POST, PUT, PATCH e na maioria das respostas. O formato mais comum em APIs modernas é JSON.

O header Content-Type: application/json deve ser enviado sempre que o body for JSON.

Body de requisição (POST)

// Enviando um body JSON
await fetch('/api/login', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ email: 'alex@senai.br', senha: '1234' }),
});

Body de resposta (servidor)

// Node.js / Express — resposta JSON
app.get('/api/users/:id', (req, res) => {
  res.status(200).json({
    id: 1,
    nome: 'Alexandre',
    cargo: 'Instrutor SENAI',
  });
});

Autenticação

O que é JWT

JWT (JSON Web Token) é um padrão aberto (RFC 7519) para transmitir informações de forma segura entre partes como um objeto JSON assinado digitalmente.

Um JWT é uma string dividida em 3 partes separadas por ponto (.):

xxxxx.yyyyy.zzzzz
   ↑       ↑       ↑
Header  Payload Signature
Header
Tipo do token e algoritmo de assinatura (ex.: HS256)
Payload
Dados do usuário (id, role, expiração…) — NÃO cifrados!
Signature
Garante que o token não foi adulterado
Atenção: O payload é apenas codificado em Base64 — não cifrado. Nunca coloque senhas ou dados sensíveis no payload.

Como o JWT funciona

O fluxo de autenticação com JWT segue este ciclo:

Cliente
faz login
→
Servidor
valida credenciais
→
Gera JWT
assina com secret
→
Retorna
token ao cliente
→
Req. protegida
envia Bearer token
→
Servidor valida
e responde
  • 1 Usuário envia e-mail e senha via POST.
  • 2 Servidor verifica as credenciais no banco.
  • 3 Se válido, gera um JWT assinado com uma chave secreta.
  • 4 Cliente armazena o token (memória, cookie httpOnly).
  • 5 Nas próximas requisições, envia o token no header Authorization: Bearer <token>.
  • 6 Servidor verifica a assinatura e valida a expiração antes de responder.

Implementando JWT — React + Node (TypeScript)

1. Instalação das dependências

# Back-end
npm install jsonwebtoken bcryptjs
npm install -D @types/jsonwebtoken @types/bcryptjs

# Front-end
npm install axios

2. Back-end — gerar e validar o token

src/auth/authController.ts
import { Request, Response } from 'express';
import jwt from 'jsonwebtoken';
import bcrypt from 'bcryptjs';

const JWT_SECRET = process.env.JWT_SECRET ?? 'troque-em-producao';

// Payload tipado
interface TokenPayload {
  userId: number;
  email: string;
}

export async function login(req: Request, res: Response) {
  const { email, senha } = req.body;

  // Busca usuário no banco (exemplo simplificado)
  const usuario = await buscarUsuarioPorEmail(email);
  if (!usuario) return res.status(401).json({ erro: 'Credenciais inválidas' });

  const senhaCorreta = await bcrypt.compare(senha, usuario.senhaHash);
  if (!senhaCorreta) return res.status(401).json({ erro: 'Credenciais inválidas' });

  const payload: TokenPayload = { userId: usuario.id, email: usuario.email };

  const token = jwt.sign(payload, JWT_SECRET, { expiresIn: '8h' });

  res.json({ token });
}
src/auth/authMiddleware.ts
import { Request, Response, NextFunction } from 'express';
import jwt from 'jsonwebtoken';

const JWT_SECRET = process.env.JWT_SECRET ?? 'troque-em-producao';

export function autenticar(req: Request, res: Response, next: NextFunction) {
  const authHeader = req.headers.authorization;

  if (!authHeader?.startsWith('Bearer ')) {
    return res.status(401).json({ erro: 'Token ausente' });
  }

  const token = authHeader.split(' ')[1];

  try {
    const decoded = jwt.verify(token, JWT_SECRET);
    (req as any).usuario = decoded;
    next();
  } catch {
    res.status(401).json({ erro: 'Token inválido ou expirado' });
  }
}

3. Front-end React — login e requisições autenticadas

src/hooks/useAuth.ts
import { useState } from 'react';
import axios from 'axios';

export function useAuth() {
  const [token, setToken] = useState<string | null>(null);

  async function login(email: string, senha: string) {
    const { data } = await axios.post('/api/auth/login', { email, senha });
    setToken(data.token);
    // Opção: salvar em cookie httpOnly pelo servidor
  }

  function logout() { setToken(null); }

  const api = axios.create({
    baseURL: '/api',
    headers: token ? { Authorization: `Bearer ${token}` } : {},
  });

  return { token, login, logout, api };
}
Boas práticas: Prefira cookies httpOnly; Secure; SameSite=Strict ao localStorage para guardar JWTs em produção — protege contra ataques XSS.

O que é Middleware

Middleware é uma função que fica no meio do ciclo de vida de uma requisição HTTP — entre o cliente e o handler final. Ela recebe o objeto request e response e decide se processa a requisição, modifica algo, ou passa adiante com next().

Requisição
→
Middleware 1
Logger
→
Middleware 2
Autenticação
→
Middleware 3
Validação
→
Handler
Resposta

Usos comuns de middlewares

TipoO que faz
LoggerRegistra método, URL e tempo de resposta de cada requisição
AutenticaçãoVerifica se o token JWT é válido antes de continuar
AutorizaçãoCheca se o usuário tem permissão para acessar o recurso
ValidaçãoValida o body da requisição (ex.: zod, joi)
CORSAdiciona headers de Cross-Origin Resource Sharing
Rate LimitingLimita número de requisições por IP/período
Error HandlerCaptura erros não tratados e retorna resposta padronizada

Criando middlewares em Express + TypeScript

src/middlewares/logger.ts
import { Request, Response, NextFunction } from 'express';

export function logger(req: Request, res: Response, next: NextFunction) {
  const inicio = Date.now();
  res.on('finish', () => {
    console.log(`[${req.method}] ${req.url} → ${res.statusCode} (${Date.now() - inicio}ms)`);
  });
  next(); // passa para o próximo middleware
}
src/middlewares/errorHandler.ts
import { Request, Response, NextFunction } from 'express';

export function errorHandler(
  err: Error, req: Request, res: Response, next: NextFunction
) {
  console.error(err.stack);
  res.status(500).json({ erro: 'Erro interno do servidor' });
}
src/app.ts
import express from 'express';
import { logger }       from './middlewares/logger';
import { autenticar }   from './auth/authMiddleware';
import { errorHandler } from './middlewares/errorHandler';

const app = express();

// Middlewares globais
app.use(express.json());
app.use(logger);

// Rota pública
app.post('/api/auth/login', login);

// Rotas protegidas — autenticar é o middleware
app.get('/api/users', autenticar, listarUsuarios);

// Sempre por último — captura erros
app.use(errorHandler);
A ordem importa: middlewares de erro precisam de 4 parâmetros (err, req, res, next) e devem ser registrados após todas as rotas.
Banco de dados

Conectar PostgreSQL com Node.js (TypeScript)

A biblioteca mais usada para conectar Node.js ao PostgreSQL é o node-postgres (pg). Ela fornece um pool de conexões e permite executar queries SQL diretamente, com total controle sobre o banco.

Instalação e configuração

# Instalação
npm install pg
npm install -D @types/pg
src/database/pool.ts
import { Pool } from 'pg';

export const pool = new Pool({
  host:     process.env.DB_HOST     ?? 'localhost',
  port:     Number(process.env.DB_PORT)  || 5432,
  database: process.env.DB_NAME     ?? 'minha_db',
  user:     process.env.DB_USER     ?? 'postgres',
  password: process.env.DB_PASSWORD ?? 'senha',
  max: 10, // máximo de conexões no pool
});
src/users/userRepository.ts
import { pool } from '../database/pool';

interface Usuario {
  id: number;
  nome: string;
  email: string;
}

export async function listarUsuarios(): Promise<Usuario[]> {
  const { rows } = await pool.query('SELECT id, nome, email FROM usuarios');
  return rows;
}

export async function buscarPorId(id: number): Promise<Usuario | null> {
  const { rows } = await pool.query(
    'SELECT id, nome, email FROM usuarios WHERE id = $1',
    [id] // parameterizado — previne SQL injection
  );
  return rows[0] ?? null;
}

export async function criarUsuario(nome: string, email: string, senhaHash: string) {
  const { rows } = await pool.query(
    'INSERT INTO usuarios (nome, email, senha_hash) VALUES ($1, $2, $3) RETURNING *',
    [nome, email, senhaHash]
  );
  return rows[0];
}

Back-end

Variáveis de Ambiente (.env)

Um arquivo .env (dotenv) armazena configurações sensíveis e variáveis que mudam entre ambientes (desenvolvimento, teste, produção) fora do código-fonte. Em vez de escrever senhas e chaves diretamente no código, você lê esses valores como variáveis de ambiente em tempo de execução.

Regra de ouro: qualquer valor que muda entre máquinas ou que não pode ser público pertence ao .env, não no código.

Por que usar variáveis de ambiente?

🔒 Segurança
Senhas, tokens e chaves secretas ficam fora do repositório — não vão para o GitHub
🔄 Portabilidade
O mesmo código roda em dev, staging e produção apenas trocando o .env
👥 Colaboração
Cada dev tem suas próprias credenciais locais sem conflito
☁️ Deploy
Serviços como Railway, Vercel e AWS injetam variáveis diretamente — sem arquivo necessário

O que NÃO deve estar no código-fonte

TipoExemplos
Credenciais de bancoUsuário, senha, host, nome do banco
Chaves secretasJWT_SECRET, chaves de API (Stripe, SendGrid…)
URLs de serviçosURL do banco, endpoint de pagamento, URL do Redis
Configurações de ambienteNODE_ENV, porta do servidor, nível de log
Credenciais de e-mailSMTP host, usuário, senha, porta

Criando um módulo de configuração tipado

Em vez de espalhar process.env.ALGUMA_COISA pelo código inteiro, centralize tudo em um arquivo de config com validação e tipagem:

src/config/env.ts
import 'dotenv/config';

function obrigatorio(chave: string): string {
  const valor = process.env[chave];
  if (!valor) throw new Error(`Variável de ambiente ausente: ${chave}`);
  return valor;
}

export const env = {
  nodeEnv:    process.env.NODE_ENV ?? 'development',
  port:       Number(process.env.PORT) || 3000,

  db: {
    host:     obrigatorio('DB_HOST'),
    port:     Number(process.env.DB_PORT) || 5432,
    name:     obrigatorio('DB_NAME'),
    user:     obrigatorio('DB_USER'),
    password: obrigatorio('DB_PASSWORD'),
  },

  jwt: {
    secret:    obrigatorio('JWT_SECRET'),
    expiresIn: process.env.JWT_EXPIRES_IN ?? '8h',
  },
} as const;
src/database/pool.ts  ← usando o módulo de config
import { Pool } from 'pg';
import { env } from '../config/env';

export const pool = new Pool({
  host:     env.db.host,
  port:     env.db.port,
  database: env.db.name,
  user:     env.db.user,
  password: env.db.password,
});
A função obrigatorio() faz o servidor parar imediatamente na inicialização se uma variável essencial estiver faltando — muito melhor do que descobrir o erro em produção durante uma requisição.

Validação avançada com Zod

Para projetos maiores, a biblioteca Zod permite validar e tipar variáveis de ambiente de forma robusta:

# Instalação
npm install zod
src/config/env.ts  ← versão com Zod
import 'dotenv/config';
import { z } from 'zod';

const schema = z.object({
  NODE_ENV:    z.enum(['development', 'test', 'production']).default('development'),
  PORT:        z.coerce.number().default(3000),
  DB_HOST:     z.string().min(1),
  DB_PORT:     z.coerce.number().default(5432),
  DB_NAME:     z.string().min(1),
  DB_USER:     z.string().min(1),
  DB_PASSWORD: z.string().min(1),
  JWT_SECRET:  z.string().min(32, 'JWT_SECRET deve ter ao menos 32 caracteres'),
  JWT_EXPIRES_IN: z.string().default('8h'),
});

const parsed = schema.safeParse(process.env);

if (!parsed.success) {
  console.error('❌ Variáveis de ambiente inválidas:');
  console.error(parsed.error.flatten().fieldErrors);
  process.exit(1); // para o servidor antes de iniciar
}

export const env = parsed.data;

JavaScript / TypeScript

O que é Promise e async/await

JavaScript é single-threaded — executa uma coisa de cada vez. Mas certas operações levam tempo: consultar um banco, chamar uma API, ler um arquivo. Se o código esperasse travado até terminar, a aplicação inteira pausaria.

A solução é o modelo assíncrono: você dispara a operação, continua executando outras coisas, e quando o resultado chegar o código retoma. Uma Promise é o objeto que representa esse valor futuro.

pending
Operação ainda em andamento
fulfilled
Concluiu com sucesso — tem um valor
rejected
Falhou — tem um erro

Estados de uma Promise

// Uma Promise começa "pending" e termina em fulfilled ou rejected
const promessa = new Promise<string>((resolve, reject) => {
  const sucesso = true;

  if (sucesso) {
    resolve('Dados carregados!'); // fulfilled
  } else {
    reject(new Error('Algo deu errado')); // rejected
  }
});

// Consumindo com .then() / .catch()
promessa
  .then((resultado) => console.log(resultado))   // 'Dados carregados!'
  .catch((erro) => console.error(erro.message)); // se rejected

async / await — a forma moderna

async/await é uma sintaxe introduzida no ES2017 que torna o código assíncrono parecido com código síncrono, sem perder os benefícios das Promises. Por baixo dos panos, é exatamente a mesma coisa.

// Sem async/await — usando .then() encadeado
function buscarUsuario(id: number) {
  return pool
    .query('SELECT * FROM usuarios WHERE id = $1', [id])
    .then((resultado) => resultado.rows[0])
    .catch((erro) => { throw erro; });
}

// Com async/await — mesmo resultado, mais legível
async function buscarUsuario(id: number) {
  const resultado = await pool.query('SELECT * FROM usuarios WHERE id = $1', [id]);
  return resultado.rows[0];
}
Regra: await só pode ser usado dentro de uma função marcada com async. Uma função async sempre retorna uma Promise — mesmo que você retorne um valor direto.

Tratamento de erros com try/catch

Com async/await, erros de Promises rejeitadas são capturados com o try/catch tradicional — muito mais claro do que encadear .catch():

async function criarUsuario(nome: string, email: string) {
  try {
    const resultado = await pool.query(
      'INSERT INTO usuarios (nome, email) VALUES ($1, $2) RETURNING *',
      [nome, email]
    );
    return resultado.rows[0]; // usuário criado

  } catch (erro) {
    // Se o e-mail já existir (UNIQUE), o banco lança erro aqui
    console.error('Erro ao criar usuário:', erro);
    throw erro; // propaga para o handler da rota
  }
}

Promise.all — executar várias em paralelo

Quando você precisa aguardar múltiplas operações independentes, Promise.all as executa em paralelo e aguarda todas terminarem — bem mais rápido do que await uma a uma:

// ❌ Sequencial — lento: espera cada um antes do próximo
const usuarios  = await buscarUsuarios();   // 200ms
const produtos  = await buscarProdutos();   // + 150ms
const pedidos   = await buscarPedidos();    // + 180ms  → total: 530ms

// ✅ Paralelo — rápido: os três rodam ao mesmo tempo
const [usuarios, produtos, pedidos] = await Promise.all([
  buscarUsuarios(),
  buscarProdutos(),
  buscarPedidos(),
]); // → total: ~200ms (o mais demorado)
Promise.all falha se qualquer Promise rejeitar. Se quiser que os outros continuem mesmo com falhas, use Promise.allSettled.

Promise em rotas Express

src/users/userController.ts
import { Request, Response } from 'express';
import { listarUsuarios, buscarPorId } from './userRepository';

// async: a função retorna uma Promise<void>
export async function getUsuarios(req: Request, res: Response) {
  try {
    const usuarios = await listarUsuarios(); // aguarda a Promise resolver
    res.json(usuarios);
  } catch (erro) {
    res.status(500).json({ erro: 'Erro ao buscar usuários' });
  }
}

export async function getUsuarioById(req: Request, res: Response) {
  try {
    const usuario = await buscarPorId(Number(req.params.id));
    if (!usuario) return res.status(404).json({ erro: 'Não encontrado' });
    res.json(usuario);
  } catch (erro) {
    res.status(500).json({ erro: 'Erro interno' });
  }
}

Back-end / Banco de dados

O que é rows

Quando você executa uma query com a biblioteca node-postgres (pg), o banco retorna um objeto QueryResult. A propriedade rows é um array com os registros que o banco encontrou — cada elemento é um objeto JavaScript correspondendo a uma linha da tabela.

// pool.query() retorna uma Promise<QueryResult>
const resultado = await pool.query('SELECT id, nome, email FROM usuarios');

// resultado é um objeto com várias propriedades:
//  resultado.rows     → array de linhas retornadas
//  resultado.rowCount → quantas linhas vieram
//  resultado.fields   → metadados das colunas

console.log(resultado.rows);
// [
//   { id: 1, nome: 'Alexandre', email: 'alex@senai.br' },
//   { id: 2, nome: 'Maria',     email: 'maria@senai.br' },
// ]

Desestruturação — o atalho mais comum

Na prática, quase sempre você só quer o array rows. O padrão mais usado é desestruturar direto na declaração:

// Sem desestruturação — verboso
const resultado = await pool.query('SELECT * FROM usuarios');
const usuarios  = resultado.rows;

// Com desestruturação — direto ao ponto ✅
const { rows } = await pool.query('SELECT * FROM usuarios');
//     ↑ extrai apenas "rows" do objeto QueryResult
const { rows } = await pool.query(...) é a mesma coisa que
const resultado = await pool.query(...); const rows = resultado.rows;
— só mais curto.

Cenários práticos

// 1. Vários registros — retorna todos como array
const { rows } = await pool.query('SELECT * FROM produtos');
// rows → [{ id:1, nome:'Teclado' }, { id:2, nome:'Mouse' }, ...]
return rows; // retorna o array inteiro

// 2. Um único registro — pega o primeiro elemento
const { rows } = await pool.query(
  'SELECT * FROM usuarios WHERE id = $1', [1]
);
// rows → [{ id:1, nome:'Alexandre', email:'alex@senai.br' }]
return rows[0]; // pega o objeto, não o array

// 3. INSERT com RETURNING — retorna a linha criada
const { rows } = await pool.query(
  'INSERT INTO usuarios (nome, email) VALUES ($1, $2) RETURNING *',
  ['Carlos', 'carlos@senai.br']
);
// rows → [{ id:3, nome:'Carlos', email:'carlos@senai.br' }]
return rows[0]; // o novo registro com o id gerado

// 4. Nenhum resultado — rows é array vazio
const { rows } = await pool.query(
  'SELECT * FROM usuarios WHERE id = $1', [999]
);
// rows → []
if (rows.length === 0) return null; // usuário não encontrado

Tipando rows com TypeScript

Por padrão, rows é do tipo any[]. Para ganhar autocomplete e segurança de tipos, passe uma interface como genérico:

src/users/userRepository.ts
import { pool } from '../database/pool';

// Define o formato de uma linha da tabela
interface Usuario {
  id:     number;
  nome:   string;
  email:  string;
}

export async function listarUsuarios(): Promise<Usuario[]> {
  // <Usuario> informa ao TypeScript o tipo de cada elemento em rows
  const { rows } = await pool.query<Usuario>(
    'SELECT id, nome, email FROM usuarios'
  );
  return rows; // rows: Usuario[]  ← tipado!
}

export async function buscarPorId(id: number): Promise<Usuario | null> {
  const { rows } = await pool.query<Usuario>(
    'SELECT id, nome, email FROM usuarios WHERE id = $1',
    [id]
  );
  return rows[0] ?? null; // Usuario | undefined → null se não achar
}
O operador ?? (nullish coalescing) retorna o lado direito quando o esquerdo é null ou undefined. rows[0] ?? null significa: "retorne o primeiro elemento, ou null se não existir".

rowCount — quantas linhas foram afetadas

Para UPDATE e DELETE, rows fica vazio (a não ser que use RETURNING). Nesses casos, use rowCount para saber se algo foi alterado:

export async function deletarUsuario(id: number): Promise<boolean> {
  const { rowCount } = await pool.query(
    'DELETE FROM usuarios WHERE id = $1', [id]
  );
  return (rowCount ?? 0) > 0; // true se deletou, false se id não existia
}

export async function atualizarNome(id: number, nome: string) {
  const { rows, rowCount } = await pool.query<Usuario>(
    'UPDATE usuarios SET nome = $1 WHERE id = $2 RETURNING *',
    [nome, id]
  );
  if ((rowCount ?? 0) === 0) throw new Error('Usuário não encontrado');
  return rows[0]; // usuário atualizado
}

O que é localStorage

O localStorage é um mecanismo de armazenamento do navegador que permite salvar dados como pares chave → valor diretamente no dispositivo do usuário, de forma persistente — os dados continuam existindo mesmo depois de fechar o navegador ou desligar o computador.

Ele faz parte da Web Storage API, disponível em todos os navegadores modernos via objeto global window.localStorage.

Origem = protocolo + domínio + porta. http://localhost:3000 e http://localhost:5173 são origens diferentes e têm storages separados.

API — os 4 métodos principais

// Salvar um valor
localStorage.setItem('chave', 'valor');

// Ler um valor (retorna null se não existir)
const valor = localStorage.getItem('chave'); // 'valor' | null

// Remover um item
localStorage.removeItem('chave');

// Apagar tudo do storage dessa origem
localStorage.clear();

// Quantos itens estão salvos
console.log(localStorage.length);

Salvando objetos com JSON

O localStorage aceita apenas strings. Para salvar objetos ou arrays, serialize com JSON.stringify e recupere com JSON.parse:

const usuario = { id: 1, nome: 'Alexandre', role: 'admin' };

// ❌ Errado — salva "[object Object]"
localStorage.setItem('usuario', usuario);

// ✅ Correto — serializa para string JSON
localStorage.setItem('usuario', JSON.stringify(usuario));

// Recuperando e convertendo de volta para objeto
const raw = localStorage.getItem('usuario');
const dados = raw ? JSON.parse(raw) : null;

Usando com TypeScript — helper tipado

Criar um helper evita repetir JSON.stringify/JSON.parse e garante tipagem em todo o projeto:

src/utils/storage.ts
export const storage = {
  set<T>(chave: string, valor: T): void {
    localStorage.setItem(chave, JSON.stringify(valor));
  },

  get<T>(chave: string): T | null {
    const raw = localStorage.getItem(chave);
    if (!raw) return null;
    try {
      return JSON.parse(raw) as T;
    } catch {
      return null; // JSON inválido
    }
  },

  remove(chave: string): void {
    localStorage.removeItem(chave);
  },
};

// Uso
interface Preferencias { tema: 'claro' | 'escuro'; idioma: string }

storage.set<Preferencias>('prefs', { tema: 'escuro', idioma: 'pt-BR' });
const prefs = storage.get<Preferencias>('prefs'); // Preferencias | null

Usando com React — hook personalizado

src/hooks/useLocalStorage.ts
import { useState } from 'react';

export function useLocalStorage<T>(chave: string, valorInicial: T) {
  const [valor, setValor] = useState<T>(() => {
    try {
      const raw = localStorage.getItem(chave);
      return raw ? (JSON.parse(raw) as T) : valorInicial;
    } catch {
      return valorInicial;
    }
  });

  function salvar(novoValor: T) {
    setValor(novoValor);
    localStorage.setItem(chave, JSON.stringify(novoValor));
  }

  function remover() {
    setValor(valorInicial);
    localStorage.removeItem(chave);
  }

  return [valor, salvar, remover] as const;
}

// Uso em um componente React
function ConfiguracaoTema() {
  const [tema, setTema] = useLocalStorage<'claro' | 'escuro'>('tema', 'claro');

  return (
    <button onClick={() => setTema(tema === 'claro' ? 'escuro' : 'claro')}>
      Tema atual: {tema}
    </button>
  );
}
